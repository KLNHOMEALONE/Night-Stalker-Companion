# RE-разбор `01_ghidra/App_bin` — вывод: статической xref-связи «строка → номер» нет

Замер 18–19.11. Инструменты: REA (Ghidra 12.2 provider) + свой побайтовый
разбор на Python (`tools/*.py`). Окружение REA работает после
`source tools/pard-env.sh` ( Temurin 21 из `tools/jdk`, `DEVELOPER_DIR` от Xcode,
иначе `libxcrun` без x86_64).

## Артефакт — это Flutter iOS AOT-снапшот, и он размечен символами

`nm -a 01_ghidra/App_bin` (всего 5 символов, из них 4 полезных):

| символ | адрес | что это |
|---|---|---|
| `_kDartVmSnapshotInstructions` | `0x4000` | начало `__TEXT.__text` |
| `_kDartIsolateSnapshotInstructions` | `0xe800` | код isolate-снапшота |
| `_kDartVmSnapshotData` | `0x4ae1c0` | == старт `__TEXT.__const` |
| `_kDartIsolateSnapshotData` | `0x4b7900` | база isolate-данных |

Секции: `__text` `0x4000+0x4aa1a0`, `__const` `0x4ae1c0+0x3ef950`
(**fileoff == vmaddr**, то есть отображение тождественное — на этом был один
баг: вычитать базу `__const` нельзя).

## Формат данных (установлен по байтам, не по догадкам)

Dart String (one-byte), заголовок 16 байт, объект 16-байтно выровнен:

```
0x7b7760  0005e232 072cea5d 0000001e 00000000   |/?custom=1&cmd=|
          class    hash      len<<1   pad        chars
```

Проверка на соседях: `dart:core/print.dart` (20 симв.) → `len=0x28`,
`Firm Update` (11) → `len=0x16`, у нашей строки (15) → `0x1e`. ✓

**Указатели в куче — 4-байтные относительные значения от `_kDartIsolateSnapshotData`
(0x4b7900); чётное = объект, нечётное = Smi.** Единственный слот во всём образе,
ссылающийся на объект нашей строки (`0x7b7760` = `0x4b7900 + 0x2ffe60`):

```
0x63bd10: 0x002ffe60 0x00054443     ; col1 -> str '/?custom=1&cmd='
```

Он сидит в таблице `0x620800..0x644780` — **18417 записей по 8 байт**
(147 KB), нашей записи соответствует индекс 13986.

## Почему Ghidra/REA тут не даёт xref (доказано, а не «не удалось»)

| проверка | результат |
|---|---|
| `ADRP` во всём `__text` | **0** (маска `w & 0x9F000000 == 0x90000000`; 4 885 000 инструкций) |
| `ADR` | есть (2042 в выборке 300k строк `otool -tV`) → код полностью PC-relative |
| релокации Mach-O (`otool -rv`, `LC_DYSYMTAB`) | `nlocalsym=0`, записей нет |
| 8-байтный абсолютный указатель на `0x7b7760` | нет (скан по всем секциям, шаг 4) |
| относительный «от держателя» / «от базы снапшота» | ровно 1 хит, `0x63bd10` (см. выше) |
| как код трогает константы | `ldr xD, [x26, #imm]` (x26 = Dart PP): 22910 мест, **159 различных смещений, максимум `0x848`** |

Следствие: рантайм-пул, на который смотрит PP, вмещает ~266 слотов
(`0x848/8`), а наша запись лежит в снапшот-таблице со смещением `0x1b510` —
это **за пределами imm12 unsigned-LDR (макс `0xff8`)**. Значит рантайм-пул
собирается из снапшота при загрузке, и в файле связи «инструкция → строка»
не существует ни в каком виде. Ни у Ghidra, ни у ручной разметки нет материала
для графа вызовов: цепочка обрывается на загрузчике Dart.

Побочный замер: `rea_list_procedures` = 21902 «функции» (Ghidra самонаходит их
сканом `__text` без точек входа), `rea_search_strings` = **0 строк** — строковые
инвентари пустые, потому что данные не размечены. То есть Ghidra на этом
артефакте работает, но бесполезна ровно по той же причине.

## Что это значит для задачи 2 из `NEXT_SESSION.md`

«Развязать `имя → число`» по iOS-бинарю за разумную цену **нельзя** — нужен
читатель Dart AOT-снапшота уровня Blutter. Проверено: `tools/blutter/README.md`
— «supports only Android libapp.so (arm64 only)»; Mach-O не читается. Плюс
`libflutter.so`/XAPK на диске отсутствуют (`find` по `~/Downloads ~/Projects
~/Desktop ~/Documents` — ни `.xapk`, ни `.apk`, ни `.ipa`, ни `libapp.so`),
а сам Blutter требует сети и сборки Dart-специфичного рантайма.

Инструменты разбора留在 `tools/`: `dump_heap_around.py` (дампа объекта + поиск
маркеров версии Dart), `relptr_scan.py` (поиск относительных указателей от
реальных баз снапшота), `table_walk.py` (границы таблицы + индекс записи),
`pp_offsets.py` (распределение `[x26,#imm]` — им и доказывается потолок `0xff8`),
`insn_hist.py`, `adrp_scan.py`, `dart_str_xref.py`, `pool_scan.py`,
`parent_scan.py`, `pool_find.py`, `pool_dump.py`.

## Рабочие альтернативы (выбрать, не повторять прошлые пути)

1. **Android XAPK + Frida/Gadget** — единственный способ получить точный
   `имя → число`: хук `Uri.parse`/`HttpClient` даёт готовую ссылку с `cmd=`.
2. **Эмпирика по проводу** (задача 1): доснять `cmd=1..8191` и сопоставить id с
   семантикой по ответам/поведению — работает без реверса, oracle уже есть.
3. Blutter по Android `libapp.so`, если XAPK вернётся: нужен `libflutter.so`
   для автоопределения версии Dart и интернет на сборку.
